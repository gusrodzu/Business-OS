Business OS — DESPLIEGUE CLOUD CANÓNICO (noviembre 2026)
=====================================================

Frontend: Cloudflare Workers Static Assets (NO Vercel)
Worker existente: business-os
URL: https://business-os.gorz12.workers.dev/
Git Build: repositorio gusrodzu/Business-OS, branch main
Comando build: npm run build
Comando deploy: npx wrangler deploy --config ./wrangler.toml
Directorio output: apps/web/dist
Fallback SPA: not_found_handling = "single-page-application"

API: Render Node (servicio independiente, verificar origen real)
PostgreSQL: servicio gestionado existente (no modificar conexiones por retirar Vercel)
Archivos: Cloudflare R2 privado, si se encuentra activado.

1) Genera variables de ejemplo y secretos sólo en tu equipo:
   .\PREPARAR-CLOUD.ps1
   Nunca subas .env.cloud.local ni secretos al repo.

2) Cloudflare Worker existente
   - En Cloudflare Workers & Pages > business-os > Builds verifica que la
     integración Git siga conectada a main.
   - Mantén VITE_API_URL con el origen HTTPS real de la API y sufijo /api.
   - Mantén los permisos del token Build de Cloudflare y el Worker existente.
   - NO crees otro Worker, NO publiques Pages y NO uses Vercel.
   - Antes de anunciar publicación, valida resultado del build, SHA y versión
     activa. Cloudflare es responsable del frontend, no del backend.

3) Backend API
   - Mantén Render, PostgreSQL y la configuración de secretos vigente.
   - Validar /api/health y /api/ready antes de un cambio operativo.
   - Revisar CORS, CLIENT_URL, cookies Secure/SameSite, CSRF y autorización
     para el dominio Workers real.
   - No migrar datos ni tocar API como parte del retiro de Vercel.

4) Seguridad frontend
   - Cabeceras en apps/web/public/_headers: CSP, HSTS, X-Frame-Options,
     Referrer-Policy, Permissions-Policy y caché segura de assets.
   - wrangler.toml contiene el fallback SPA; los JSON de Vercel están
     deliberadamente eliminados.

5) GitHub y CI
   - Los flujos de QA de GitHub Actions siguen vigentes (lint, build, seguridad,
     rutas, smartphone, PostgreSQL e integración).
   - Validar: npm run release:final y el test
     node --test scripts/validate-cloudflare-pages-policy.test.mjs
   - Un error de la app externa Vercel no implica un fallo de compilación de
     Cloudflare; desconecta la app externa siguiendo:
     docs/deployment/RETIRAR_VERCEL.md

6) Smoke después de publicar
   - Probar ruta / y deep links de Inventario, Compras y Ventas.
   - Comprobar autenticación, empresas aisladas y permisos; no usar credenciales
     reales en capturas ni logs.
   - Verificar responsive móvil 320/360/390/430, tablet y escritorio.
   - Probar PWA, CSP/caché y conexión HTTPS a la API si corresponde.

Las políticas históricas de Vercel siguen disponibles únicamente en Git History.
